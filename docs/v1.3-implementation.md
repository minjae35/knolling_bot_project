# v1.3 implementation decisions

The user's implementation request authorizes dataset changes; the attached
specification's historical document-only clauses do not override that request.
Neural/model/training/simulation sections remain out of scope.

Baseline: 69cf565. The Desktop checkout was fast-forwarded from f372f76 without
rewriting history. The old pilot was copied from the previous workspace after
verifying all 1,041 file hashes and the specified manifest SHA-256. Neither copy
is a migration output. Legacy audits support a read-only mode.

## Policies and determinism

`teacher_legacy.py` preserves the exact baseline implementation bytes. The
low-level Teacher dispatcher retains its legacy default; the active builder and
annotation APIs now select `balanced_rows_v1.3` with English instructions by
default. Legacy reproduction must select `legacy_v1_2` explicitly. Dataset
provenance, rather than the currently installed code, identifies its policy.
The new policy generates sequential and balanced partitions with k=1..N_selected,
deduplicates by observable-order index tuples, and ranks globally by the specified
rounded scores. Partial candidates use exact polygon validation; the legacy SAT
gap test is sufficient but not necessary and could discard a lower-movement
diagonal candidate. The M5 predicates themselves are unchanged.

An observed-row template requires at least two selected objects, axes within 5°
of a common table axis, row block centers agreeing within 5.1 mm, horizontal gaps
>=9.9 mm and mutually consistent within 5.1 mm, separated row bands, and exact
requested size order/color purity/contiguity. New direction/gap/region are not
required of the old arrangement. This conservative operational definition avoids
inventing existing rows from scattered singleton objects. It is not a claim that
the scene has a known interactive history. These tolerances follow existing M5
row/axis/gap limits, with 0.1 mm numerical allowance.

New vertical targets use -pi/2. Immutable sources, locked poses and no-ops retain
their exact original representation, including legacy +pi/2. Migration compares
physical angles modulo pi and centers with 1e-12 m tolerance; representation-only
changes do not require a new image. All raw and canonical target hashes are kept.

The policy/config hash is distinct from the code revision. No schema fields or
dataclass meanings are changed. Audit/policy/review information goes in sidecars.

## Verified Partial coverage

The 30 original Partial samples select 1/2/3/4 objects in 11/11/2/6 samples.
All originally selected objects move. Eleven single-object examples are useful
for grounding/keeping other objects, but do not supervise pairwise knolling.
The current source-generation process produces scattered arrangements; organized
source episodes and multi-turn coverage are not established by geometric validity.
Migration preserves this distribution; any proposed additions require a separate
dataset change rather than silent resampling.

## Migration, review and audit contracts

The CLI defaults new builds to the balanced policy; legacy reproduction must be
explicit. Fixed-input migration recognizes the registered legacy manifest hash,
rejects nested or occupied output directories, copies independent source files
and immutable parent metadata, and checks the complete parent tree before/after.
No source generator is invoked in migration. Only physically changed targets
produce Blender jobs; reused views keep their original bytes and hashes.

`teacher_audit.jsonl` records exact candidate counts, template keys, scores,
configuration and target hashes. `migration.jsonl` records old/new rows and scores,
render decisions and change classes. Policy reproduction, semantic language
invariance, object-array invariance, asset aliases and re-applied No-op are checked
for every new sample. Counterfactual and Partial-quality sidecars are recomputed
by the independent dataset audit. Original split decisions and source values are
compared to the hash-verified parent annotations.

Human ratings are null and approvals pending for all 130 review cards. The only
completion marker is `AUTOMATED_VALIDATION.json`; `training_approved.jsonl` is
empty. This phase does not export training subsets. A future export must require
recorded human review and the specification's quality gate; automatic geometry
or the absence of audit errors must never supply those ratings.

Results, the 57 changed targets and coverage recommendations are recorded in
[the completed migration report](v1.3-pilot-report.md).

## English-only active language policy

`pilot_v1_3_en` is derived by changing only the original v1.3 text and language.
The original bilingual artifact remains untouched. The same Teacher, source/target
geometry, identities, assets, scene families and splits are retained; no scene
sampling or rendering occurs. Geometry validation may reproduce Teacher outputs
as an audit, but never installs a recomputed target during language conversion.

English wording comes from structured fields and source-visible referents, with
no translation service or neural language model. The audit checks canonical
English wording, every immutable annotation field, render hashes and split indexes.
The default audit targets the English artifact; archived audits require explicit
legacy mode. Fresh balanced builds also use English and English QC. Historical
parent annotations cannot enter training through recursive file discovery.

Only English is supported in the initial system. A multilingual-capable pretrained
text encoder does not change this product/data policy; its architecture remains
unchanged. Optional English-encoder comparisons belong to the Neural Pilot.
